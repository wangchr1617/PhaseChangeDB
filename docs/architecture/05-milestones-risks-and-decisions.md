## 2. 避免重复造轮子：深度技术选型与论证

在第二轮演进中，坚决反对在成熟领域“自研低劣简易替代品”。以下是核心组件的选型决策与边界：

### 2.1 学术文献元数据抽取与解析
- **拒绝**：继续手写纯正则表达式扫描 PDF 二进制内容（容错率极低、无法处理双栏排版与复杂表格）；
- **采纳**：**“DOI 探测 + Crossref REST API / OpenAlex API 权威拉取”混合流水线**；
  - **选型理由**：绝大多数相变材料文献（发表于 Nature Materials, Advanced Materials, Acta Materialia 等）均有明确 DOI；直接通过官方 Crossref API 拉取元数据，能够在 1 秒内获得 100% 准确的出版年份、标准化期刊全称与缩写、全部作者英文全名与 DOI 外部链接；
  - **许可证与风险**：Crossref 与 OpenAlex 为开放学术基础设施，API 免费提供且支持无限制学术调研；设置 3 秒超时与本地 PDF 纯文本提取作为自动降级回退。

### 2.2 知识图谱前端交互与渲染
- **拒绝**：手写 1000 行原生 HTML5 Canvas 绘制节点坐标与连线（缺乏力导向物理引擎、缺乏平滑碰撞避让、难以扩展多跳分析）；
- **采纳**：**`Cytoscape.js`**（或基于 WebGL 的 `react-force-graph`）；
  - **选型理由**：`Cytoscape.js` 是生物信息学与材料拓扑网络事实上的工业级开源标准，内置 cose-bilkent 等顶尖力导向布局算法，原生支持节点多级邻居选择、子图过滤与高性能视口拖拽缩放；
  - **许可证**：MIT，极其商业友好且代码体积极小。

### 2.3 前端异步数据请求与服务端状态缓存
- **拒绝**：在各个组件内裸调 `fetch` 并手动写数十个 `useState(loading)` 与 `useState(error)`；
- **采纳**：**`@tanstack/react-query` (TanStack Query v5)**；
  - **选型理由**：统一管理服务端数据缓存（Cache）、数据失效（Invalidation）、后台自动重试、窗口聚焦刷新与分页无缝加载，消灭 80% 的样板代码；
  - **许可证**：MIT。

### 2.4 大模型结构化物性抽取
- **拒绝**：手写脆弱的字符串截取与非结构化提示词模态框；
- **采纳**：**Pydantic + 官方 Google GenAI SDK (Structured Outputs / JSON Schema)**；
  - **选型理由**：已有 `app/domain/pcm_extraction_schema.py` 已经定义了严密的物性与测试条件 Pydantic 校验规则；利用官方大模型原生受限生成能力（Constrained Decoding），使模型输出强制符合 JSON Schema，杜绝语法解析错误；
  - **许可证**：Apache 2.0。

## 3. 核心技术风险、影响分析与应对预案 (Risk Management)

| 风险类别 | 风险描述 | 触发概率 | 潜在影响 | 应对预案与规避措施 |
| :--- | :--- | :---: | :---: | :--- |
| **技术债务** | 拆分 `MySQLCatalogRepository` 导致部分边缘查询回归破坏 | 中 | 高 | 1. 采用 **门面模式（Facade Pattern）**：拆分底层子仓储，但老类保持原方法签名并进行简单代理调用；<br>2. 严格执行“改动前运行测试、改动后运行测试”机制，任何失败立即一键回滚。 |
| **网络与外部依赖** | Crossref API 在国内网络环境下偶发访问受限或延时波动 | 中 | 中 | 1. 设置严格的客户端超时（`timeout=3.0s`）；<br>2. 建立本地内存与 SQLite 缓存，相同 DOI 绝不重复请求；<br>3. 超时或网络异常时，平滑无感回退至本地提取模式，绝不阻断用户。 |
| **安全漏洞** | 用户配置的大模型 Key 泄露或被恶意利用代理进行大量刷量 | 低 | 严重 | 1. 密钥全生命周期 AES-256-GCM 加密落库，且仅在后端中继时解密，严禁进日志；<br>2. 代理端点限制单 IP 请求频次（Rate Limiting，如 10 次/分钟）；<br>3. 用户输入验证强化，防范 SSRF 探测内网。 |
| **科学数据质量** | 大模型从文献中抽取出错误的相变温度数值或颠倒升温速率 | 高 | 严重 | 1. **物理合理性边界检查**：在领域层设定相变物性合理区间（如结晶温度 $T_c \in [300, 1000]\text{ K}$）；<br>2. **严防直写权威表**：所有模型提取必须停留在 `ext_candidate` 暂存区，必须经人工专家复核后方可晋升。 |

## 4. 关键技术评审与待决问题 (Decisions & Open Questions)

为确保团队达成统一的技术与产品认知，以下两项设计建议供技术委员会评审决策：

### 决议 1：大模型代理与密钥配置模式
- **选项 A（纯服务端自建）**：系统后端统一在环境变量配置官方模型 Key，用户免配任何 Key 开箱即用，由系统提供每日限额（成本由平台承担）；
- **选项 B（纯用户自备 BYOK）**：系统不提供官方模型，必须由用户自行输入个人 Gemini / OpenAI Key，仅提供端到端加密代理；
- **架构师推荐方案（混合双模）**：
  - 默认提供少量免费体验额度（使用系统官方 Key）；
  - 针对需要高通量大批量处理文献的高级科研用户，支持在设置面板中填入个人 API Key，享有无限制并发通道。

### 决议 2：知识图谱可视化技术栈
- **选项 A（Cytoscape.js）**：专注于 2D 拓扑科学图谱，布局严谨、算法成熟、支持复杂子图与属性过滤，适合严肃科学分析；
- **选项 B（react-force-graph 3D）**：基于 Three.js / WebGL，视觉效果极为炫酷震撼，适合演示汇报，但对密集节点的精细连线点击操作不如 2D 精确；
- **架构师推荐方案**：
  - 第二轮 MVP 核心选择 **`Cytoscape.js`**，确保科学数据排查的严谨性与精准交互；在长期演进中可将 3D 视图作为可选视角供用户自由切换。
